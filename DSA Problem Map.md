# 🧠 Pattern Expansion Rule

This repository will **not** create a pattern folder just because a DSA sheet has it.

A pattern gets added when:

1. I have solved a problem that genuinely belongs to it, or
2. I encounter the pattern while expanding the complete problem list.

This keeps the repository useful instead of filling it with empty folders.

# 📌 Standard Problem Folder

Every completed problem should follow:

```
Topic/
└── Pattern/
    └── problem-name/
        ├── solution.cpp
        └── README.md
```

Every problem README should contain:

- Problem
- Pattern
- Pattern Recognition Cue
- My Thought Process
- Brute Force
- Optimal Solution
- Alternative / Reference Solutions
- Dry Run
- Time Complexity
- Space Complexity
- Key Takeaway

# 🎯 Revision Philosophy

> **Don't memorize 500 solutions. Recognize 85 patterns.**

When I see a new problem, the goal is:

```
Problem
   ↓
What is changing?
   ↓
What is the constraint?
   ↓
Which pattern fits?
   ↓
Brute Force
   ↓
Optimization
   ↓
Optimal Solution
```

That is the skill I am building for placements, contests, and technical interviews.
